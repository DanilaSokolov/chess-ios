# Как сделаны 3D-фигуры

Фигуры на 3D-доске не скачаны, а построены в коде: модуль
[`ChessModels`](../apple/ChessCore/Sources/ChessModels) превращает описание фигуры в
треугольники. Он не зависит от RealityKit и Metal: на выходе обычные массивы чисел,
которые потом отдаются любому движку.

```
профиль фигуры ──► Shapes.lathe / extrude / box ──► MeshData ──┬─► RealityKit (MeshDescriptor) — доска в игре
(точки «радиус, высота»)                            (массивы)   ├─► Model I/O (MDLMesh) — файлы .usdc
                                                                └─► Metal (буферы) — как в уроке 3
```

## 1. Из чего состоит модель

[MeshData.swift](../apple/ChessCore/Sources/ChessModels/MeshData.swift) — три массива:

- `positions` — где находится каждая вершина (x, y, z);
- `normals` — куда «смотрит» поверхность в этой вершине. От нормали зависит
  освещение: поверхность, повёрнутая к свету, яркая, отвёрнутая — тёмная;
- `indices` — каждые три числа образуют треугольник из вершин с такими номерами.

**Порядок обхода.** У треугольника две стороны. Лицевой считается та, с которой вершины
идут против часовой стрелки; изнанку движки обычно не рисуют (в уроке 3 это
`setCullMode(.back)`). Перепутанный порядок — частая ошибка: фигура «исчезает» кусками.
Здесь от неё защищает `addTriangle`: он сам разворачивает треугольник так, чтобы
лицевая сторона смотрела туда же, куда нормали. А тест `trianglesFaceOutward` проверяет
это для каждого треугольника каждой фигуры.

**Гладко или с ребром.** Если у соседних треугольников общая вершина с общей нормалью,
свет плавно перетекает — поверхность выглядит круглой. Чтобы получить острое ребро
(низ основания, грани креста), вершины дублируют: одна копия с нормалью одной грани,
вторая — другой. Поэтому у куба 24 вершины, а не 8.

## 2. Три способа построить форму

[Shapes.swift](../apple/ChessCore/Sources/ChessModels/Shapes.swift):

- **`lathe` — токарный станок.** Профиль (половина силуэта) вращается вокруг оси.
  Так сделано почти всё: настоящие фигуры тоже точат на станке. Каждая точка
  профиля становится кольцом из 49 вершин, соседние кольца сшиваются треугольниками.
  Повтор точки в профиле даёт острое ребро.
- **`extrude` — формочка для печенья.** Плоский контур выдавливается на толщину.
  Так сделана голова коня: её не выточить на станке. Плоские крышки контура
  разбиваются на треугольники методом «отрезания ушей» (`triangulate`).
- **`box` и `sphere`** — зубцы ладьи, крест короля, шарики короны ферзя.
  Сфера — тоже `lathe`, только профиль у неё — полуокружность.

## 3. Фигура = профиль + детали

[PieceModels.swift](../apple/ChessCore/Sources/ChessModels/PieceModels.swift). Например, пешка:

```swift
Shapes.lathe(
    foot(radius: 0.34)                                    // общее для всех основание
        + [[0.2, 0.17], [0.15, 0.24], [0.12, 0.33], [0.105, 0.42]]   // ножка
        + collar(at: 0.43, inner: 0.105, outer: 0.19)     // воротничок
        + Shapes.arc(center: [0, 0.62], radius: [0.13, 0.13], from: -58, to: 90, steps: 14)  // голова
)
```

Единица длины — клетка доски. Фигура стоит на y = 0, конь смотрит в сторону −z
(на чёрных); чёрные фигуры на доске разворачиваются на 180°.

## 4. Как это попадает на экран

В [Board3DView.swift](../apple/ChessApp/Board3DView.swift) массивы превращаются в
`MeshDescriptor` → `MeshResource`, по одному на вид фигуры: все пешки делят одну
сетку, отличается только материал. Материал — `PhysicallyBasedMaterial`: цвет,
шероховатость 0.32 и прозрачный лак (`clearcoat`), который даёт блики.

## Посмотреть модели отдельно

```bash
make models     # пересоздаст apple/Models/*.usdc
open apple/Models/white-knight.usdc
```

Файлы открываются в Xcode, Reality Composer Pro и Blender (импорт USD).
Model I/O не умеет писать `.usdz`, поэтому формат `.usdc` — тот же USD, только не
упакованный в архив.

## Что уже сделано — и как

Упражнения 2–6 из первой версии этого разбора выполнены. Разберите, как именно:

| Было упражнение | Где смотреть | Суть |
|---|---|---|
| Гранёные фигуры | `PieceModels.mesh(for:segments:)`, кнопка с кубиком рядом с 2D/3D | Число долек токарного станка — параметр. При 8 видно, что «круглое» — много плоских граней. Нормали при этом по-прежнему сглажены, поэтому свет переливается, а силуэт гранёный. |
| Конь объёмнее | `Shapes.extrude(_:thickness:bevel:)`, `Shapes.inset` | Крышки контура уменьшены на 0.045 (`inset` сдвигает каждую точку внутрь по биссектрисе угла), а между крышкой и боком — наклонная полоса с нормалью «наискосок». На полосе играет свет — голова перестаёт быть пластиной. |
| Прорезь слона | `PieceModels.accent(for:)`, тест `slitSitsOnTheMitre` | Настоящий надрез — это вычитание одного тела из другого (CSG), отдельная большая тема. Здесь — тонкая тёмная пластина, наклонённая и утопленная в митру так, что наружу торчит только край спереди. Первая версия была шире митры и торчала «ушами» по бокам: тест теперь это ловит. |
| Пешка на чистом Metal | урок 5, [`Lesson5Pieces`](Sources/Lesson5Pieces/main.swift) | Те же массивы `MeshData` — в четыре буфера GPU. Главный подвох: `SIMD3<Float>` в Swift занимает 16 байт, а не 12. Урок 3 оставлен как был — он про Model I/O. |
| Текстура дерева | `WoodTexture`, `apple/Models/wood.png`, `Board3DView.makeWood` | Картинка не скачана, а посчитана формулами: полосы + шум. Она бесшовная (тест `woodTextureTiles`), поэтому повторяется без стыков. Серая, а цвет даёт материал: слоновая кость или эбен. UV у `lathe`: u — угол поворота, v — путь вдоль профиля, поэтому волокна идут вдоль оси, как у точёного дерева. |

Первая версия текстуры была в 2 раза чаще и сильно волнистой — на фигурах получалась «полосатая скатерть». Поправлено: 6 волокон на оборот вместо 22 и мягче контраст. Хороший урок: текстуру всегда проверяют на модели, а не только картинкой.

## Упражнения

После каждого изменения: `swift test -c release --package-path apple/ChessCore`
(тесты проверят, что фигура цела) и запуск приложения в режиме 3D.

1. **Своя пешка.** Поменяйте профиль пешки: голову побольше, ножку потоньше.
   Посмотрите, что будет, если убрать повтор точки в `foot` — пропадёт острое ребро внизу.
2. **По-настоящему плоские грани.** В гранёном режиме нормали всё ещё сглажены.
   Сделайте в `lathe` вариант, где у каждой дольки свои вершины с одной нормалью
   на дольку (как у `box`). Сравните, как меняется свет.
3. **Скос у зубцов ладьи.** Зубцы — простые `box`. Сделайте их через `extrude`
   с `bevel`, как голову коня.
4. **Текстура на доске.** Клетки доски пока однотонные. Наложите на них ту же
   `WoodTexture`, повернув волокна на светлых и тёмных клетках по-разному.
5. **Нормальная карта.** Волокна сейчас только цветом. Посчитайте из той же
   формулы карту нормалей (наклон поверхности по соседним пикселям) и отдайте её
   в `PhysicallyBasedMaterial.normal` — волокна станут рельефными на бликах.
6. **В уроке 5:** выполните упражнения в конце файла — особенно первое, с шагом 12:
   увидеть ошибку выравнивания своими глазами полезно один раз в жизни.
